长上下文速览（Long Context，2023 ~ 2026）

从「attention sink」到「稀疏注意力」· 重点看架构与算法设计 · 检索时间 2026-08-23 · 每篇 = 配方 + 一句话（问题 / 方法 / 核心）

0. 记法（这个领域的「最大公约数」）

长上下文的核心矛盾是：注意力是 O(n²) 的、且 KV 缓存随长度线性增长。所以所有方法都在回答三件事——注意力怎么做、KV 怎么管、长度怎么外推。配方围绕这三轴：

记号意思
dense全注意力（每个 token 看所有历史），O(n²)
sparse稀疏注意力：滑窗 + 全局/检索/block，子平方复杂度
linear线性注意力 / SSM，O(n)
gated在注意力输出上加门控（非线性 + 稀疏）
evictKV 驱逐：按分数/规则丢掉不重要的 KV
sinkattention sink：保留/学习几个「吸收注意力」的 sink token
rope / yarn / hope / alibi位置编码与外推：RoPE / YaRN / HoPE / ALiBi

配方格式：模型: <注意力> -> <上下文/复杂度> [KV·位置机制]。例：StreamingLLM: dense -> 无限流式 [sink + 滑窗]。

1. 主线：一条「attention sink」的兴衰史

  1. 2023 发现：StreamingLLM 发现「attention sink」——初始几个 token 会吸收大量注意力，直接滑窗会崩；H2O 发现注意力是重尾的，可以驱逐大部分 KV。
  2. 2025 解决：OpenAI GPT-OSS 把 sink 做成内置可训练参数；Qwen3-Next 的 Gated Attention 用门控直接消除 sink（sink-free）。sink 从「要绕开的问题」变成「设计选项」。
  3. 2025-2026 之后：sink 不再是瓶颈，注意力转向「原生稀疏注意力」——NSA / MoBA / HiLS 等，把稀疏性做成端到端可训练、硬件对齐，追求 64K → 1M → 16M 上下文。

三条并行轴：注意力复杂度（dense → sparse → linear）、KV 记忆（full → evict → sparse-access）、长度外推（RoPE → YaRN/HoPE → sink-free）。

2. Attention Sink 专章（核心叙事）

StreamingLLM：Efficient Streaming Language Models with Attention Sinks（2309.17453，ICLR 2024）
StreamingLLM: dense -> 无限流式 [sink + 滑动窗口]
问题 流式推理时只保留最近 token 的滑窗会崩、质量骤降；方法 发现「attention sink」——初始几个 token 吸收大量注意力（softmax 的副产品），保留这几个 sink token + 最近 token 即可无限流式；核心 首次命名 attention sink，奠定「sink 必须留」的认知。

H2O：Heavy-Hitter Oracle for Efficient Generative Inference（2306.14048，NeurIPS 2023）
H2O: dense -> KV 压缩 [evict 非 heavy-hitter]
问题 KV cache 随长度线性增长、撑爆显存；方法 发现注意力分数是重尾的——少数「heavy hitter」token 贡献大部分注意力，保留它们 + 最近 token、驱逐其余；核心 KV 驱逐派的开山之作，带理论保证。

GPT-OSS（OpenAI 开源模型，2025-08）（HF）
GPT-OSS: dense + 内置 sink -> 128K [trainable sink 参数]
问题 sink 一直被当成「要绕开的 bug」，各家用 workaround；方法 把 attention sink 做成模型内置、可训练的一等参数（soft_max_add_sinks），20B/120B MoE、128K 上下文；核心 sink 从「问题」变成「设计特性」，标志着它被正式接纳并解决。

Gated Attention：Non-linearity, Sparsity, and Attention-Sink-Free（2505.06708，NeurIPS 2025，Qwen3-Next）
Gated Attention: gated -> sink-free [head 级 sigmoid gate]
问题 sink 与 massive activation 一起损害训练稳定性和长上下文外推；方法 在 SDPA 之后加 head 级 sigmoid 门控，引入非线性 + 稀疏性，直接消除 attention sink；核心 「sink-free」：不用再特殊照顾 sink，还顺带提升长上下文外推，Qwen3-Next 已采用。

sink 被 GPT-OSS 和 Gated Attention 两个方向分别「解决」之后，长上下文研究的主战场转向了稀疏注意力架构：不再纠结 sink，而是把稀疏性做成原生、端到端可训练、硬件对齐，去冲 64K → 1M → 16M 上下文。下面这章就是「之后的新变化」。

3. 稀疏注意力（2024-2026，sink 之后的主战场）

Landmark Attention（Random-Access Infinite Context）（2305.16300，NeurIPS 2023）
Landmark: sparse(landmark) -> 无限上下文 [检索式随机访问]
问题 全注意力算不了无限长；方法 每个 block 用 landmark token 做代表，query 先检索相关 block 再做局部注意力；核心 检索式稀疏注意力的早期代表。

RingAttention with Blockwise Transformers（2310.01889，ICLR 2024）
RingAttention: dense(分块环形) -> 近无限上下文 [分布式分块注意力]
问题 长序列单卡放不下、注意力矩阵爆炸；方法 把序列分块、按环在设备间传递 KV，块与块之间做注意力；核心 用「分布式分块」把 dense 注意力扩到百万级长度。

MInference（Dynamic Sparse Attention）（2407.02490，2024）
MInference: sparse(动态) -> 10× 加速 [免训的动态稀疏模式]
问题 长上下文预填充太慢；方法 免训练地识别 A-shape / Vertical-Slash / Block-Sparse 三种动态稀疏模式并据此计算；核心 不训练、动态稀疏，prefill 加速一个数量级。

NSA（Native Sparse Attention，DeepSeek）（2502.11089，ACL 2025）
NSA: sparse(压缩+选择+滑窗) -> 64K [原生可训练 + 硬件对齐]
问题 稀疏注意力要么不可原生训练、要么硬件不友好；方法 三路并行——token 压缩、token 选择、滑动窗口——统一成硬件对齐的算子，原生端到端训练；核心 「原生稀疏 + 硬件对齐」成为这条线的标杆。

MoBA（Mixture of Block Attention，Moonshot/Kimi）（2502.13189）
MoBA: sparse(block 路由) -> 10M [MoE 式 block 选择]
问题 稀疏注意力怎么既高效又能选对 block；方法 把 MoE 的路由思想搬到注意力：每个 query 只路由到少数相关 block；核心 「注意力也 MoE 化」，Kimi 跑到 10M 上下文。

SeerAttention（Learning Intrinsic Sparse Attention）（2410.13276，2025）
SeerAttention: sparse(学习式) -> 90% 稀疏 [端到端学注意力阈值]
问题 手工稀疏规则不通用；方法 让模型端到端学习「哪些注意力该保留」的阈值，达到内在稀疏；核心 「学出来的稀疏」而非手工设计。

InfLLM-v2（Dense-Sparse Switchable Attention）（2509.24663）
InfLLM-v2: dense↔sparse 可切换 -> 短长自适应 [语义块检索]
问题 短上下文要 dense、长上下文要 sparse，二者难兼得；方法 dense/sparse 可切换的注意力，短时全注意力、长时检索稀疏；核心 无缝短到长自适应。

HiLS Attention：Hierarchical Sparse Attention Done Right（种子论文）（2607.02980，2026）
HiLS: sparse(层级 landmark) -> 64× 外推 [端到端 chunk 检索]
问题 现有 chunk-wise 稀疏注意力 chunk 选不准、追不上 full attention；方法 层级 landmark 稀疏：query 先对各 chunk 独立算注意力提取 chunk 信息，再按检索分数融合，检索分数直接进前向、用 LM loss 端到端优化；核心 检索分数可端到端学习、原生稀疏训练，64× 外推仍有 90% 检索准确率，现有 full-attention 模型轻量续训即可转换。

DashAttention（Differentiable Adaptive Sparse Hierarchical Attention）（2605.18753）
DashAttention: sparse(可微层级) -> 长上下文 [可微自适应稀疏]
问题 层级稀疏注意力不够可微、选择不够自适应；方法 可微 + 自适应的层级稀疏注意力；核心 把稀疏选择做进可微框架。

NOSA（Native and Offloadable Sparse Attention）（2510.13602）
NOSA: sparse(原生+可卸载) -> 超长上下文 [可 offload 到 CPU]
问题 超长上下文的 KV 显存放不下；方法 原生稀疏注意力 + 支持把不活跃 KV offload 到 CPU；核心 稀疏 + 卸载，突破显存上限。

MiniMax Sparse Attention（2606.13392）
MiniMax SA: sparse(块+局部) -> 超长上下文 [层次化块稀疏]
问题 稀疏注意力在真实长文本上仍不稳；方法 层次化块稀疏 + 局部窗口，训练与推理都稀疏；核心 工业级稀疏注意力的落地。

4. KV 驱逐 / 压缩（H2O 之后的演进）

H2O 开了「驱逐不重要的 KV」这条路，后面主要是把「什么重要」判定得更准、更层自适应、更低开销。

SnapKV（2404.14469）
SnapKV: evict -> KV 压缩 [观察窗口投票选重要 KV]
问题 H2O 的逐 token 分数不稳定；方法 用一个「观察窗口」在 prompt 末尾统一投票选出最重要的 KV；核心 免训、稳定的 KV 压缩。

PyramidKV（2406.02069）
PyramidKV: evict -> 金字塔式 KV [浅层留多、深层留少]
问题 每层 KV 重要性不同、却用同一预算；方法 按「浅层多留、深层少留」的金字塔分配 KV 预算；核心 层自适应预算。

Quest（2406.10774）
Quest: evict -> 低开销压缩 [用 Q 做重要性估计]
问题 现有驱逐要算满注意力分数、开销高；方法 只用量化后的 query 做重要性估计，绕过完整注意力；核心 近零开销的 KV 驱逐。

5. 位置编码 / 长度外推

另一条路不动注意力、只改位置编码，让训练时 4K 的模型直接外推到 128K/1M。

RoPE（Rotary Position Embedding）（2104.09864）
RoPE: 旋转位置编码 -> 相对位置 [复数旋转]
问题 绝对位置编码难表达相对距离；方法 用旋转矩阵把位置编码进 QK 内积；核心 现代 LLM 默认位置编码，长上下文研究的起点。

ALiBi（2108.12409）
ALiBi: 线性偏置 -> 免训外推 [相对距离惩罚]
问题 位置编码外推能力差；方法 给注意力加「随距离线性衰减」的偏置，不学位置编码；核心 零外推成本的早期方案。

YaRN（2309.00071）
YaRN: RoPE 频率缩放 -> 128K 外推 [NTK + 温度]
问题 RoPE 直接外推会崩；方法 NTK-aware 频率缩放 + 注意力温度修正；核心 主流的免训/微调外推方案。

LongRoPE（2402.13753）
LongRoPE: 非均匀频率 -> 2048K 外推 [进化搜索旋转角]
问题 均匀缩放频率损失短上下文精度；方法 用进化搜索找非均匀的旋转角缩放；核心 首次外推到 2048K。

HoPE（High-frequency rotary Position Encoding）（ACL 2025）
HoPE: 只留高频 -> 无长期衰减 [去掉低频分量]
问题 RoPE 的长期衰减让远处 token 交互变弱；方法 只保留 RoPE 的高频分量、去掉低频，从理论上打破长期衰减；核心 位置编码与「长期衰减」解耦。

6. 线性注意力 / SSM（另一条路）

不稀疏化、也不驱逐，而是换掉 softmax 注意力本身，把复杂度从 O(n²) 压到 O(n)。

RWKV（2305.13048）
RWKV: linear -> O(n) [RNN 式线性注意力]
问题 Transformer 是 O(n²)；方法 把注意力改成线性（可写成 RNN 递推）；核心 O(n) 的 LLM 路线代表。

Mamba（Selective State Space Model）（2312.00752）
Mamba: linear(SSM) -> O(n) [输入依赖的选择性状态]
问题 线性注意力/SSM 表达力弱；方法 让状态转移参数依赖输入（选择性 SSM）；核心 线性复杂度 + 内容感知，SSM 路线的复兴。

7. 训练数据与 Benchmark（单独一节）

长上下文不止是架构问题，也是「用什么数据训、用什么 benchmark 测」的问题。这条线回答：怎么把 4K 的模型训成 128K/1M，以及怎么客观测出真实上下文长度。

7.1 长上下文训练

LongLoRA（Efficient Fine-tuning of Long-Context LLMs）（2309.12307）
LongLoRA: 稀疏局部注意力微调 -> 100K [shifted sparse attention]
问题 把长上下文模型全量微调太贵；方法 用 shifted sparse attention 做参数高效微调；核心 低成本把 Llama 扩到 100K。

ABF（Adjusting Base Frequency / YaRN 前的基频调参）（2401.07879）
ABF: 调 RoPE 基频 -> 外推 [大基频=长波长]
问题 RoPE 外推需要正确基频；方法 分析并调大 RoPE 的 base frequency；核心 外推训练的关键超参。

OLMo-3 / Dolma3（Allen AI，长上下文续训数据）（HF）
OLMo-3-1025: 续训 -> 长上下文 [Dolma3 长文本语料]
问题 公开长上下文模型缺透明训练数据；方法 全开源的 7B 长上下文续训模型 + Dolma3 语料；核心 开源长上下文训练的可复现基线（HiLS 等论文的续训底座）。

7.2 Benchmark

LongBench（2308.14508）
LongBench: 双语多任务 -> 长上下文理解 [6 类 21 任务]
问题 缺一个系统的长上下文理解评测；方法 中英双语、单文档/多文档/检索/摘要/代码/合成六类任务；核心 最常用的长上下文理解 benchmark。

RULER（2404.06654）
RULER: 合成检索任务 -> 真实上下文长度 [合成 needle]
问题 「宣称 128K」和「真能用到 128K」是两回事；方法 用合成检索（变体 needle-in-haystack）测有效上下文长度；核心 揭示大多数模型的实际可用长度远低于宣称值。

L-Eval（2307.11088）
L-Eval: 长序列评测 -> 多任务 [20 类任务]
问题 早期缺标准化长序列评测；方法 覆盖推理/问答/摘要等 20 类长任务；核心 早期长上下文评测标准之一。

InfiniteBench（2402.13718）
InfiniteBench: 100K+ 评测 -> 极长上下文 [检索/推理/长链任务]
问题 需要 100K+ 级别的真实任务评测；方法 构造 100K 以上的检索、推理、长链依赖任务；核心 极长上下文的压力测试。

8. 共识与分歧（速记版）

共识：

  1. attention sink 已被「内置 sink 参数」（GPT-OSS）或「门控消除 sink」（Gated Attention）两个方向解决，不再是瓶颈。
  2. 稀疏注意力是当前主战场，方向收敛为「原生可训练 + 硬件对齐 + 端到端检索」（NSA / HiLS）。
  3. KV 驱逐和位置编码外推是「免训/低成本」的实用路线，仍大量用于推理加速。
  4. 「宣称的上下文长度」远大于「实际可用长度」，RULER 成了事实上的照妖镜。

分歧 / 难点：

  1. 稀疏 vs 线性 vs 密集：稀疏注意力（NSA/MoBA）质量高但结构复杂，线性/SSM（Mamba）简单但表达力受限，谁最终胜出未定。
  2. 稀疏选择可不可微：手工规则（MInference）vs 端到端可微（HiLS/SeerAttention）——后者好但难训。
  3. 长度外推 vs 原生长训练：靠位置编码外推（YaRN/HoPE）省算力但天花板低，原生长上下文训练贵但上限高。
  4. 评测：合成任务（RULER）与实际长文本任务（LongBench）结论常不一致，缺统一标准。
